# alonim-research

דף נחיתה ומעבדת התנסות מחקרית עבור תוכנית המצוינות **"אלונים"** במרכז האקדמי רופין.

**נושא המחקר:** הקשר בין אינהיביציה (Inhibition) לפעולות החלפה בשטף מתמטי (Math Fluency / Switching).
**מנחה אקדמית:** ד"ר ירדן גליקסמן · **חוקרים:** טל אלאיוף ומאיה פילו.

🔗 [alonim-research.chuk-app.workers.dev](https://alonim-research.chuk-app.workers.dev)

---

## עקרון תכנוני: אפס בקשות רשת

האתר מיועד להיפתח מיידית מסריקת QR בטלפון אנדרואיד, גם תחת קליטה סלולרית חלשה במיוחד,
וגם ללא חיבור לאינטרנט כלל. לכן `index.html` הוא **קובץ יחיד וסגור**:

| רכיב | מימוש |
|---|---|
| CSS | Tailwind מקומי, מקומפל מראש ומוטמע inline — רק הקלאסים שבשימוש בפועל |
| פונטים | מחסנית מערכתית (`Segoe UI` / `system-ui` / `Noto Sans Hebrew` / Arial) — ללא Google Fonts |
| גרפיקה | SVG וקטורי מוטמע בקוד (אילוסטרציות הסמסטרים, אייקונים) |
| QR | SVG וקטורי מוטמע — ללא שירות QR חיצוני |
| סקריפטים | Vanilla JS מוטמע — ללא ספריות |

**התוצאה:** ~120KB raw, ~25KB בהעברה (gzip), **בקשת רשת אחת בלבד** — הקובץ עצמו.
לשם השוואה, הגרסה הקודמת טענה את Tailwind Play CDN (~400KB + קימפול בדפדפן ב-runtime),
שלוש בקשות ל-Google Fonts ותמונת QR משרת חיצוני.

⚠️ **אסור להוסיף לקובץ תגי `<link>` או `<script src>` לדומיינים חיצוניים.** סקריפט הבנייה נכשל בכוונה אם מתגלה הפניה חיצונית.

### תמונות תוכן — הגישה ההיברידית

שתי תמונות הסמסטרים (בסקשן `#gorilla-journey-slider`) הן צילומים, ולכן הטמעתן ב-base64
הייתה מנפחת את הטעינה הראשונית פי עשרה. במקום זה:

1. **LQIP מוטמע** — תצוגה מקדימה מטושטשת ברוחב 20px (‏184 תווי base64 כל אחת) יושבת inline כ-`background-image`.
   היא מוצגת **מיידית**, יחד עם ה-HTML, כך שאין שטח לבן ריק ואין קפיצת פריסה.
2. **WebP נטען עצלנית** — הקובץ המלא (900px, ‏q76 — ‏84KB ו-100KB) יושב ב-`assets/`,
   נטען ב-`loading="lazy"` ודוהה פנימה מעל ה-LQIP כשהוא מוכן.

התוצאה: הטעינה הראשונית נשארת **~26KB בבקשה אחת**, והתמונות נכנסות אחריה בלי לעכב דבר.
`width` ו-`height` מפורשים על כל `<img>` — אפס Cumulative Layout Shift.

### הסליידר סמסטר א' ➔ סמסטר ב'

שתי התמונות מוערמות זו על זו באותה במה. פס ההחלקה (`#semester-range`) הוא `input[type=range]`
מעוצב, והאטימות של תמונת סמסטר ב' נגזרת ישירות מערכו — כלומר ההחלקה **מדהה בין התמונות
באופן רציף**, לא מחליפה אותן בקפיצה. בשחרור הפס נתפס לקצה הקרוב (`snapSemester`).
התווית, הכיתוב וצבעי הכפתורים מתחלפים בחצייה של 50%.

הפס מסובב ב-`transform: scaleX(-1)` כדי שההחלקה תתחיל מימין (סמסטר א') ותתקדם שמאלה,
בהתאם לכיוון הקריאה בעברית. גובה אזור המגע 44px — תקן המינימום להפעלה נוחה באצבע.
`prefers-reduced-motion` מכובד.

ב-`file://` זה עובד כל עוד תיקיית `assets/` נמצאת ליד `index.html`. אם צריך קובץ בודד נייד לחלוטין,
צריך להטמיע גם אותן ב-base64 — ולשלם על כך ~350KB בטעינה הראשונית.

## מבנה הפרויקט

```
alonim-research/
├── index.html           ← הפלט הבנוי. זה הקובץ שנפרס. לא לערוך ידנית!
├── src/
│   └── index.html       ← קובץ המקור לעריכה (מכיל את הסמן /*__TAILWIND_CSS__*/)
├── assets/              ← תמונות התוכן (WebP) — הקבצים היחידים שאינם מוטמעים
├── src.css              ← נקודת הכניסה של Tailwind
├── tailwind.config.js   ← ערכת הצבעים, הפונטים והאנימציות של הפרויקט
├── build.mjs            ← מקמפל את ה-CSS ומטמיע אותו ב-index.html
├── test.mjs             ← בדיקות אוטומטיות (Playwright)
└── package.json
```

## עבודה שוטפת

```bash
npm install     # פעם אחת
npm run build   # עורכים את src/index.html ואז בונים
npm test        # בדיקות אוטומטיות מלאות
```

לתצוגה מקומית פשוט פותחים את `index.html` בדפדפן (`file://` נתמך במלואו) או דרך Live Server.

⚠️ **עורכים רק את `src/index.html`.** `index.html` שבשורש נדרס בכל בנייה.
Tailwind סורק את `src/index.html` (ולא את הפלט) — אחרת כל קלאס חדש לא היה מקומפל,
כי הפלט נכתב רק *אחרי* שה-CSS כבר קומפל.

## פריסה

Cloudflare Workers (`alonim-research.chuk-app.workers.dev`), קבצים סטטיים ללא build command בצד השרת — `index.html` שבשורש נפרס כמו שהוא.
לכן חובה להריץ `npm run build` ולעשות commit ל-`index.html` המעודכן לפני push.

## חוזה לוגי של מעבדת ההתנסות

מעבדת ההתנסות מדמה את **ניסוי 3 (Interleaved)** מתוך מערך המחקר בפלטפורמת Gorilla.

### מיפוי מקשים (זהה לכל הניסויים בפרויקט)

| מקש | פלנקר | חשבון |
|---|---|---|
| `F` | החץ המרכזי פונה **שמאלה** | המשוואה **שגויה** |
| `J` | החץ המרכזי פונה **ימינה** | המשוואה **נכונה** |

### מפתח התשובה נגזר מהגירוי — לא מוגדר ידנית

כדי למנוע היפוכי לוגיקה (באג שהיה קיים בגרסאות קודמות), אף פריט גירוי אינו נושא `key` קשיח.
המפתח מחושב מהגירוי עצמו ב-`withKeys()`:

* `flankerKey(text)` — קורא את **התו האמצעי** בלבד ומחזיר `J` לחץ ימינה, `F` לחץ שמאלה.
* `mathKey(text)` — מחשב בפועל את המשוואה ומחזיר `J` אם היא נכונה, `F` אם שגויה.

כל גירוי חדש שמוסיפים לרשימות מקבל אוטומטית את התשובה הנכונה. `test.mjs` מאמת את כל הפריטים.

### רצף הסשן (6 צעדים)

| צעד | מטלה | סוג |
|---|---|---|
| 1–4 | פלנקר | `flanker` |
| 5 | חשבון ראשון, **מיד אחרי** הפלנקרים | `math_switch` — מעבר מטלה |
| 6 | חשבון שני, אחרי מטלת חשבון | `math_repeat` — חזרה על מטלה |

**עלות המעבר (Switch Cost) = RT(צעד 5) − RT(צעד 6).**

שני הצעדים הם אותה מטלה בדיוק, ולכן ההפרש ביניהם מבודד את עלות המעבר עצמה.
אם אחד משני הצעדים נענה בטעות, התוצאה מסומנת כלא-תקפה — בדיוק כפי שצעדים שגויים מסוננים מהניתוח בניסוי האמיתי.
